# 合成与出帧

## 缓冲与同步

`luminaria_compose` 是内置的渲染器（`plug.Renderer`）。它持有 GPU 设备和所有纹理，各按调用方的键存：
dmabuf 和单像素缓冲按缓冲键，shm 按表面键，合成器图像和软件光标按各自的键，渲染目标按它分配的键。
`Display` 只转交 server 的事件（`BufferNew`、提交、销毁），并决定何时把缓冲还给客户端；放置表里的
纹理也只是键。

### shm

- 池映射一次（描述符允许时可写，截屏要往里写；否则只读），`resize` 时重新映射。客户端内存只借给
  `with_shm` 的闭包，带 SIGBUS 安全窗口：客户端中途截断文件也只会读到零，不会让合成器崩溃；视图出不了
  闭包，池之后被扩容或销毁也不会读到已解除的映射。
- 每个**表面**一张纹理（而不是每个缓冲一张）：Wayland 的损坏是相对上一个提交的缓冲而言的，纹理里
  正好就是上一次显示的内容，所以只上传损坏矩形就对。
- **合并上传**（借鉴 Quartz 的 Coalesced Updates）：提交只记下缓冲和损坏的外接矩形，放入去重的脏表面队列；
  帧开始时只遍历脏队列按表面各上传一次（O(脏表面)），然后立刻 `wl_buffer.release`。一帧之内被新提交替换掉的缓冲不拷贝，直接释放。
- 上传只按紧凑行距把损坏覆盖的字节拷进上传环（`write_texture_rect`），所有上传在这一帧的绘制之前提交。

### dmabuf

- 支持 **1..4 平面**（单 BO 与 `DISJOINT` 多 BO，通过 Linux `statx` 设备号与 inode 去重并分别绑定
  `vkBindImageMemory2`）：每路复制的描述符原子管理，导入失败时调用方所有 fd 保持原样未关。
- `BufferNew` 时立即导入（不等到第一次提交），导入的代价不落在提交路径上；结果回答 `create`，
  或让 `create_immed` 的坏缓冲按协议报错。
- 按**缓冲**缓存纹理，重复 attach 不再导入。X 格式在 view 上把 alpha 设为 1。
- 客户端销毁了还在显示的缓冲：纹理保留到表面换缓冲为止。
- 缓冲被替换后，等显示过它的输出翻出新的一帧（GPU 和显示都不再读它）才释放；显式同步的客户端在
  同一时刻打释放点。直接扫描输出或提升在硬件 overlay 平面上的缓冲，显示仍持有时不释放。

### 格式表

linux-dmabuf 的格式表由 GPU 可采样的格式与修饰符组成（`dmabuf_modifiers`），主设备是 GPU 的
DRM 节点；DRM 后端时把主平面能直接扫描输出的组合放在单独的扫描输出分组里排在前面，客户端会优先
按那种布局分配缓冲，直接扫描输出更容易成立。

## 放置表落地

合成器给的是一张全局逻辑坐标的放置表。每次布局、表面树或尺寸变化、动画推进时重建；重建过程（`place.mica`）复用
上一次的暂存缓冲，稳态不拷贝整个放置表或弹出菜单表，不分配临时 `Map`/`List`，并按表面 key 建立 O(1) 索引：

1. 先将弹出菜单按根表面预索引到 `popups_by_root`，并在没有 layer 表面时走快速路径跳过遍历；
2. 对每个窗口：取表面树（子表面按叠放顺序，带偏移），窗口几何原点对齐到布局位置，乘上 `scale`；
   再按父链从 `popups_by_root` O(1) 取并放置它的弹出菜单（父表面原点 + 父几何偏移 + 弹出菜单几何 − 自身几何偏移）。
3. 对每个输出：与输出的逻辑矩形求交，换算成该输出的像素（位置、尺寸取整，保证清晰），带上视口源、
   缓冲变换、不透明区域、圆角和阴影（只给根表面）。
4. 记录每个表面的全局原点（给输入用）、所属窗口 `surf_window` 和命中矩形。
5. 表面所在输出的位图变化时发 enter / leave，按其中最大的缩放发首选缩放。
6. 所有 seat 的软件光标（seat0 仅在无硬件光标平面时，辅助 seat 总是用软件纹理）放在最上面。

`luminaria_compose`（与 `vk_compose.Scene`）把每个输出的放置表按 **key**（表面或图像的 id）以 O(1)
`Map` 索引增量比对进场景：先哈希查找现有条目与更新（只有几何或样式变了才算损坏，只换纹理不算——
内容变化由提交的损坏说明），批量紧缩移除消失 key（`remove_many`），若顺序变了用 O(N log N) 耐心排序
最长递增子序列（LIS `reorder`）仅重排并损坏最少数量的新移位条目。没变的放置不产生任何损坏。

`transition_ms` 的动画在这一步插值：每个 key 记住目标和起点，用缓出三次曲线按当前时间算出位置和
不透明度；动画进行中输出保持变脏，每帧重建一次。

## 合成

由 `vk_compose` 和 `vk_draw2d` 完成：

- 损坏区域最多 8 个整像素矩形；加上按目标图像缓冲年龄补的最近 4 帧历史。
- 一个 render pass 里，每个损坏矩形一次带裁剪的实例化绘制，只画落入它的形状。
- 遮挡剔除：每个矩形从完全盖住它的最上层不透明形状开始画；全屏不透明窗口只画一个四边形。
- 纹理坐标是仿射映射，裁剪和八种 `wl_output.transform` 没有额外开销。
- 色彩管理与 HDR：按输出支持 8-bit（BGRA8/RGBA8）、10-bit（`A2R10G10B10` / `A2B10G10R10`）与 FP16（`R16G16B16A16_SFLOAT`）渲染目标与懒加载管线，单 pass 内完成 sRGB / scRGB / BT.2020 PQ / HLG 转换与扩展 Reinhard 色调映射；SDR 输出且源表面均为 SDR 时走零分支直通。
- 隐私遮罩：未录屏时零开销；录屏期间若输出含 `Style.block_capture` 窗口（或其弹出菜单），仅对该次捕获离线合成并将受保护表面替换为懒分配的 1×1 纯黑纹理，不影响主输出与直接扫描输出。

## 合成器时钟

每个输出一个时钟（`luminaria.clock`，属于门面的帧调度，与渲染器无关）：

- 记住上一次 vblank 的时间和序号，用翻转时间戳跟踪真实刷新间隔（1/8 平滑）。
- 帧开始时间 = 下一个还来得及的 vblank − 余量。余量初始 3 ms，最小 1 ms；落后一个 vblank 才显示的帧
  让余量加 1 ms（上限半个刷新周期），按时的帧让它减 0.1 ms。
- VRR 时有东西要显示就开始，但两帧之间不短于最短刷新间隔。
- `Frame` 事件带这一帧瞄准的 vblank 时间，给合成器推进动画。

## 出帧

输出在有损坏、动画进行中，或显示过的表面在等帧回调时才调度：按时钟的开始时间挂一个定时器；开始时间
已过就直接到期。到期发 `Frame`，等合成器处理完这一批事件后出帧：

1. 上传合并好的 shm 内容。
2. **直接扫描输出**：场景报告某个视图单独铺满输出（不透明、不缩放、不变换、不裁剪、导入的
   dmabuf、在最上面）时，把它的缓冲直接交给显示端：KMS 上导入成 framebuffer、原子测试通过才翻转，
   带上这个缓冲本次的损坏作为 `FB_DAMAGE_CLIPS`；嵌套时直接交给父合成器。客户端要求撕裂时用异步
   翻转。零拷贝，GPU 不参与。
3. 否则**合成**：向输出端取一个空闲的渲染目标（带缓冲年龄；输出端还没有或尺寸变了时先报
   `Need(Want)`，渲染器按要的尺寸、格式、修饰符造出来交给它，旧的退还给渲染器释放）。没有截屏
   等待时，从上到下取 `overlay_candidates`，过滤掉被上层非 overlay 视图/shm 窗口或 layer 遮挡的
   平面后，交由显示端执行原子 `TEST_ONLY`（`be.test_overlays`），并通过 `comp.set_overlays` 将
   成功提升的视图从主合成 pass 中跳过；再在主目标上只画剩余损坏；没有可画的（且无新 overlay
   提交时）就不提交。渲染器提交后交回 sync_file，输出端交给显示端（KMS 的 `IN_FENCE_FD`、嵌套时
   作为 dmabuf 的隐式栅栏），把这一帧变化的矩形交给 KMS（`FB_DAMAGE_CLIPS`）或父合成器（damage）。
   所有缓冲都在显示中时这一帧推迟到下次翻转。
4. 有截屏在等这个输出时：上一步不做直接扫描输出和 overlay 提升。输出 shm 截屏在合成后读回整幅
   图像交给客户端；输出 dmabuf 截屏由 `copy_dmabuf` 在 GPU 上零拷贝复制目标像素并返回 `sync_file`，
   窗口截屏由 `render_offscreen` / `render_offscreen_dmabuf` 独立渲染窗口表面树而不污染主输出场景，
   `sync_file` 进入 epoll 就绪后才发 `ready` 并触发 `wl_buffer.release`。
5. 给这一帧可见的表面发帧回调；看不见的表面不发，它们自然停帧。
6. 翻转完成（`Presented`）：给这些表面发呈现反馈、解除 fifo 屏障，释放到期的缓冲和释放点，更新时钟，
   再看是否还要调度下一帧。

## 设备内存、GPU 优先级与设备丢失恢复

- 设备内存按内存类型分块：块从 4 MiB 起、每新开一块翻倍，到 64 MiB（小堆的 1/8）为止；超过最大块一半的
  请求单独分配；空出的块除每类最后一块外立即释放。嵌套运行一个 foot 时显存约 17 MB、GTT 约 20 MB。
- 打开 Vulkan 设备时按 `Realtime` -> `High` -> `Medium` -> `Default` 尝试请求 `VK_KHR/EXT_global_priority`，
  不受特权许可或扩展缺失时静默回退，实际授予值记入 `Stats.gpu_priority`。
- 遇到 `VK_ERROR_DEVICE_LOST`（提交、等待或取得目标失败时）：`Display` 调用 `be.reset_targets`
  回收显示端持有的目标，`comp.recover` 在保持相同 `dev.id` 与对外句柄的同时重建 `vk.Device` 与管线，
  `Display` 随后为活跃窗口、shm 表面、单像素、dmabuf、合成器图像和软件光标重新上传或导入纹理并重建
  场景，最后发出 `Event.GpuReset`，计入 `Stats.gpu_resets`。

## 测量

`Display.stats(o)` 给出输出 `o` 自上次 `reset_stats` 以来测到的（每帧几次整数加法，样本是 1024 个的环）：

| 量 | 含义 |
|---|---|
| `frames` / `scanned_out` / `missed` | 上屏的帧、其中直接扫描输出的、比瞄准的晚一个 vblank 的 |
| `intervals` | 相邻两帧上屏的间隔（超过 500 ms 的空闲不算），`stats.percentile` 取 P50 / P95 / P99 / 最大 |
| `frame_ns` | 一帧从开始到交给显示端：上传、录制、提交 |
| `damage_rects` / `damage_pixels` | 交给显示端的损坏 |
| `commits` / `tests` / `merged` / `failed` / `late` | 原子提交、`TEST_ONLY`、并进别的提交的、失败的、晚于余量的 |
| `stalls` / `flip_timeouts` | 事件循环卡顿、驱动不翻转（提交线程的看门狗） |
| `overlays` | 使用了硬件 overlay 平面的已呈现帧数 |
| `policy` / `priority` / `software` | 事件循环的调度策略与优先级（或 nice）、渲染器没有 DRM 节点（CPU 光栅化） |
| `gpu_priority` / `gpu_resets` | 实际获得的 Vulkan 队列全局优先级、GPU 设备丢失恢复次数 |

`tests/probe.mica` 是性能门禁：无头 1280x720@240 Hz，50 个圆角带阴影的窗口，输入按 1000 Hz 拖动最上面
一个，指针跟着。损坏有精确上界（每帧不超过新旧两处位置加光标，局部重画坏了立刻失败）；时间上界默认
宽松，用 `LUMINARIA_GATE_INTERVAL_US`、`LUMINARIA_GATE_FRAME_US`、`LUMINARIA_GATE_MISSED` 在目标设备上
收紧。

## 遮挡报告

每次出帧后检查窗口是否还有可见部分。连续 500 ms 不可见发 `Occluded(w, true)`，重新可见发
`Occluded(w, false)`；`accept` 据此发 `suspended` 状态，让被遮住的客户端彻底停下来。
