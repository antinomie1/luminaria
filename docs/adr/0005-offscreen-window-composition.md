# ADR 0005：整窗特效走离屏合成，一帧因此不再只有一个 pass

日期：2026-08-15
状态：已实现

## 背景

要做的是带背景模糊、圆角与轻动画的混成器。这三样东西有一个共同的前提，而这个前提和现有
渲染路径是冲突的。

一个 toplevel 不是一张图，是一棵树：父表面、它的子表面，以及挂在它上面的 popup。`Frame`
的摆位串把这棵树摊平成若干个独立的四边形，`render_to()` 从后往前逐个画上去。只要每个四边形
都是不透明地各画各的，摊平就没有损失。

一旦特效作用在**整扇窗**上，摊平就开始出错：

- **透明度**。把窗口淡出，做法不是把每个表面各自按 50% 画一遍。两个表面重叠的地方会被混合
  两次，接缝处比别处亮，而且层数越多越亮。正确的做法是先把这棵树按原样合成成一张图，再把
  这张图按 50% 画一次。
- **圆角**。角要切在窗口的轮廓上。单个表面根本不知道自己是不是在窗口的角上——子表面可能
  正好压在角上，也可能离得远。这个问题在摊平之后无法回答。
- **缩放 / 平移动画**。逐表面缩放会让子表面的相对位置在取整处抖动，而且每个表面各采样一次
  的结果与整窗采样一次不同。
- **背景模糊**。模糊要采样"这扇窗背后的东西"，也就是需要一个已经合成好的下层结果可供采样。

Hyprland 与 niri 各自独立地得出了同一个结论并且都实现了它：Hyprland 在窗口 alpha ≠ 1 或
需要变换时先渲染到 per-monitor 的 offload framebuffer 再整体贴回；niri 的开窗 / 关窗 /
缩放动画同样先把窗口渲染到离屏纹理再对纹理做动画。两边的理由都是上面第一条。

## 决定

引入**离屏合成目标**：一块既能作为渲染目标、又能作为采样源的 GPU 图像。一棵表面树先按
原样（全不透明、无特效）合成进去，得到的那张图再作为**一个**四边形画到输出上，特效施加在
这一次绘制上。

渲染器一侧的形态：

- `OffscreenTarget` —— 内部持有一个 `GpuTexture`（图像、内存、视图、以及缓存的 descriptor
  set 都归它），外加这块图像上的两个 framebuffer。`texture()` 交出来的就是下一个 pass 的
  采样源。
- `render_offscreen()` —— 与 `render_to()` 是同一段代码，只有两处 barrier 不同（见下）。
- 格式带 alpha，底色通常是全透明：这里合成的是一扇窗而不是一屏，它没盖到的像素必须在贴回
  输出时透出壁纸。
- 没有 `OutputMapping`。离屏图像是它自己的像素空间；输出的缩放与旋转在**贴回时**施加一次，
  作用于合成好的整窗，而不是作用于每个表面——这本来就是离屏存在的理由之一。
- `Frame::begin_group()` / `compose_group()` —— group marker 之后的摆位先合成进目标；源摆位留在
  列表里做命中测试但不再画，目标纹理以一个最终摆位替代它们的像素。prepass 的 out-fence 自动并入
  最后上屏的 render wait 链，client acquire / release 与 damage 仍归 `Frame`，不落给混成器手工接线。

实现上之所以便宜，是因为现有 render pass 的 initial/final layout 就是
`eColorAttachmentOptimal`，进出显示引擎（foreign 队列 / `eGeneral`）全部由 pass **之外**的
显式 barrier 完成。于是离屏路径复用同一批 render pass 与管线，只把那两个 barrier 换成
"不转移队列所有权，收尾停在 `eShaderReadOnlyOptimal`"——正好是 `render_to()` 期待每个源
纹理所处的 layout，所以贴回那一趟不需要任何额外过渡。

## 代价，以及明确不做的事

**一帧不再只有一个 pass。** 这是本 ADR 真正推翻的东西。在此之前"一次 `render_to` 就是一帧"
是可以依赖的：帧的成本是一个 pass、一次提交、一条 fence 链。现在带特效的窗口每扇多一个
pass，多一块窗口大小的图像。

因此：

- **默认不启用。** 不带特效的窗口仍旧直接画进扫描输出目标，一个 pass。离屏是按窗口选择进入
  的路径，不是新的默认路径。
- **离屏目标必须缓存并复用。** 每帧新建一块窗口大小的图像会把稳态零分配的账全部推翻
  （`test_render_alloc` 守着这条）。归属放在 `Frame` 那一层，按窗口缓存，尺寸变了才重建。
- **damage 会被特效改变语义。** 模糊半径会让脏区扩散：模糊窗口底下任何东西变了，它自身那块
  就得重画，下层的 damage 还要按半径膨胀。摆位串 diff（已实现）是这件事的前提，但不是全部；
  真正接模糊时还要在摆位上标出"这块会把身后 r 像素拉进来"。
- **不做保留场景图。** ADR 0001 不因此动摇。离屏目标是**渲染资源**的缓存，不是窗口树的
  副本：它跨帧存在的只有那块显存，窗口的位置、层次、特效参数仍然每帧从摆位串重建。这条界线
  要守住——一旦离屏目标开始携带"这扇窗是谁、它在哪"，它就变成场景图了。

## 被否掉的选项

- **给 `Placement` 加一个 alpha 字段就完事。** 单表面窗口对，多表面窗口在重叠处露接缝，
  而这在真实客户端上是常态（GTK/Qt 的菜单、tooltip、视频层都是子表面）。做出来就是一个
  已知要返工的版本。
- **在片元着色器里按窗口 id 做一次性混合。** 需要知道"这个像素属于哪扇窗、这扇窗一共有几层"，
  等于把树的信息塞进逐像素状态，比多一个 pass 贵且更难说清。
- **只对没有子表面的窗口开特效。** 规避而不是解决，且客户端随时可能长出一个子表面，导致
  特效在用户看来时有时无。
