# 不做保留模式场景树

外壳层每帧由混成器现搭一个 `Placement` 列表（即时模式），而不是维护一棵跨帧存活的场景树。
`src/scene/scene.cppm` 因此删除。

## 为什么

保留树是**第二份真相**：窗口的真相已经在混成器自己的数据结构里，多一棵树就多一处要同步、
要在客户端销毁时清空、要跟 subsurface 树对齐的状态。`SceneSurface` 的悬空指针回归测试就是
这笔账的利息。

而它并没有换来保留模式该有的好处。`scene_rects()` 每帧新建 vector、每帧全树遍历，带 damage
的重载还先建全量再过滤——**付了即时模式的全部成本，外加维护树的成本**。增量 damage、免重建的
命中测试、缓存的绝对坐标，一样都没兑现。

成本量级也不支持"树更快"：桌面负载是 10–50 个窗口 / 100–300 个表面，填一个 POD 数组是几微秒，
60Hz 的预算是 16,600 微秒。吃掉预算的永远是像素，不是列表。

决定性的旁证：仓库里**没有任何消费者用过它**——两个示例都各自手搓每帧图层列表，只有它自己的
三个测试在用。

## 参照

- **wlroots** 的 `wlr_scene` 是同一个东西，且是**可选**的，于是生态分裂成"用 scene 的"和
  "自己写渲染循环的"两派，两条路径都半残。本库因此规定外壳层**不可选**（但不持有窗口状态）。
- **sway 1.9+ / SwayFX** 直接用 `wlr_scene`；SwayFX 要做圆角/模糊/阴影，相当一部分复杂度花在
  跟这棵树掰手腕上——树只知道"这里有一块纹理"，不知道"这块纹理要先采样它背后的东西"。
- **Hyprland** 从不使用 `wlr_scene`：它每帧即时遍历自己的 monitor→workspace→window 模型。
  这是本决定采用的形态。

## 后果

即时模式真正的开销是**每帧堆分配**，不是遍历。`GpuTextureFill::opaque` 是一个内含 vector 的
`Region`，每帧每表面拷一次就是一次 malloc。外壳层因此必须持有**跨帧复用的帧缓冲区**：`Frame`
活在输出上而非栈上，`clear()` 保留 capacity，opaque 区用指向共享 arena 的 span。
**稳态下每帧零分配**是这条决定的验收条件。

`output_layout` 与 `direct_scanout` 与树无关，随 `scene/` 目录一并移走。
