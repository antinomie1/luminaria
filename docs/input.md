# 输入

## 路径

```
设备 ──▶ backend（libinput + xkb / 父合成器 / inject）──▶ Display
    指针移动：先夹在输出范围内，立即移动光标（光标平面在下一个 vblank 前提交，帧先到就并进帧）
    操纵进行中：直接移动或缩放窗口，不产生事件
    其余：Key / Modifiers / ModifiersOn / Motion / Button / Scroll / Touch / Gesture 事件 ──▶ 合成器
          ──▶ 合成器自己处理（快捷键），或 accept(e) ──▶ 路由给客户端
```

修饰键状态总是立即发给键盘焦点客户端，不管合成器是否拦下了这次按键，客户端看到的修饰键始终一致。

## 命中测试

指针每动一次就要问一次"下面是哪个表面"（1000 Hz 的鼠标、几百个表面），所以做成结构数组加整数
SIMD：

- 每个已放置的表面一个矩形，取整到逻辑像素，按 8 个一组存成四个 `i32` 数组（不足 8 个用永远不命中
  的矩形补齐）。
- 一组 8 个一次判断：`(x − x0) | (x1 − x − 1) | (y − y0) | (y1 − y − 1)` 的符号位为 1 就在外面，
  四次逐通道减法、三次或、一次 `bitmask()`。
- 从最上面一组往下找，组内从最高位往下逐个用表面的输入区域确认。

512 个表面最坏情况 252 ns。浮点 `vec8` 加 `[8]bool` 逐通道检查的写法反而比标量慢（1473 ns 对
323 ns），所以没有用。

## `accept` 的路由与多 seat

每个 seat（主 `seat0` 与 `add_seat` 创建的次级 seat）各自独立维护指针坐标、命中聚焦表面、
按住按钮时的隐式抓取、触摸点表面映射、弹出菜单抓取栈、`focus_on` 窗口焦点、XKB 状态与光标纹理
（`seat0` 优先硬件光标平面，次级 seat 由渲染器合成软件光标）；输入法弹出窗放置在活跃 seat 的文本
光标下，on-demand layer 表面按席位点击获焦（`clicked_on`）。

- **指针**：按住按钮时目标固定为按下时的表面（隐式抓取），否则取命中测试结果；目标变化时发 leave /
  enter（带表面坐标），否则发 motion。指针离开所有客户端时恢复默认光标。
- **按钮**：先更新目标；有弹出菜单在抓取且点在它们之外，就关掉所有抓取中的弹出菜单。
- **滚动**：发给指针下的表面，滚轮带 v120。
- **键盘**：发给键盘焦点；`XF86Switch_VT_1..12`（Ctrl+Alt+Fn）切 VT。
- **触摸**：按下时命中测试定下目标，之后的移动、抬起都发给那个表面，坐标换算成它的表面坐标。
- **弹出菜单抓取**：`xdg_popup.grab` 把键盘焦点给弹出菜单；最后一个弹出菜单关掉后焦点回到
  `focus` 指定的窗口。
- **键盘归属**的优先级：锁屏表面（指针所在输出的）> exclusive 的顶层 / 覆盖层 layer 表面 > 抓取中的
  弹出菜单 > 点击过的 on-demand layer 表面 > `focus` 的窗口。
- **相对运动**：每个 `Motion` 同时发加速前后的增量给 zwp_relative_pointer。
- **手势**：滑动、捏合、长按交给手势开始时指针下的客户端。
- **指针约束**：指针在约束区域内、且该客户端有键盘焦点时生效。锁定时指针位置不变（只有相对运动，
  不发 `wl_pointer.motion`），限定时每次移动夹回区域；焦点离开就解除，锁定按客户端的位置提示放回光标。

## 操纵快速路径

借鉴 DirectManipulation：交互式的移动、缩放、平移在库内按输入事件驱动，每个事件直接改窗口的偏移并
标记输出变脏，不经过合成器策略，也不等下一轮事件循环。

| 操纵 | 每个输入事件 | 结束 |
|---|---|---|
| 移动 | 偏移 = 起始偏移 + 指针位移 | 按钮全部抬起，发 `Moved(w, dx, dy)` |
| 缩放 | 按边算新尺寸，夹在客户端的最小 / 最大尺寸内；**同时只有一个 configure 在途**，客户端答复后才发下一个；左边、上边缩放时随确认的尺寸移动窗口，保持对边不动 | 按钮抬起，去掉 resizing 状态再 configure 一次，发 `Resized(w, dx, dy, width, height)` |
| 平移 | 滑动手势的位移加到整个布局上，速率平滑跟踪 | 手势结束后按速率继续滑动，速度每 300 ms 衰减到 1/e，足够慢时停下，发 `Panned(dx, dy)` |

`accept(RequestMove)` / `accept(RequestResize)` 默认就启动对应操纵。偏移叠加在合成器的布局上，直到
收到结果后合成器的下一次 `layout`，所以合成器在拖动过程中重新布局也不会让窗口跳回去。
